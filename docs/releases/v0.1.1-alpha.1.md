# Release `v0.1.1-alpha.1`

Security remediation and release-hardening prerelease for `kennedy-mosoti-dev` (`https://kennedy.mosoti.dev`), following the Daybreak security review of `v0.1.0-alpha.1` (`a7e66ab`).

## Security Remediations

1. **[High] Release workflow ancestry and version binding (`.github/workflows/release.yml`)**
   - Added `fetch-depth: 0` and explicit fetch of protected `refs/heads/main` into `refs/remotes/origin/main` in both `build` and `publish` jobs before building, attesting, or publishing.
   - Enforced `git merge-base --is-ancestor "${GITHUB_SHA}" refs/remotes/origin/main` and verified `${GITHUB_REF_NAME#v}` matches `[workspace.package] version` in `Cargo.toml` in both jobs.
   - Added verification in `publish` that `RELEASE-EVIDENCE.json` `.version` and `.commit` match the tagged release before attestation and release upload.
   - Retained 40-hex commit SHA pinning for every GitHub Action.

2. **[Medium] Dynamic wiki search DoS hardening (`/wiki` and `/wiki/search`)**
   - Enforced pre-allocation bounds on raw query strings (`<= 256` bytes) and percent-decoded `q` parameters (`<= 128` bytes, `<= 16` terms, valid UTF-8) using stack-allocated decoding, returning HTTP `400 Bad Request` (`Cache-Control: no-store`) with all CSP and security headers preserved.
   - Removed per-request `WikiSearchIndex::build` and full `SiteContent` cloning from SSR `/wiki?q=...`, reusing the startup-built `&state.wiki_search` index via `render_wiki_search_page`.
   - Added `dynamic_no_cache_response` / `dynamic_error_response` to skip per-request BLAKE3 `ETag` hashing on dynamic `no-cache` search responses.
   - Added semaphore-backed concurrency gating and execution timeouts (`SearchLimitConfig`, `503 Service Unavailable` / `504 Gateway Timeout`) on dynamic search routes (`GET` and `HEAD`), backed by negative, zero-ETag, and concurrency tests.

3. **[Medium] Complete public struct field coverage in `check_privacy_and_nda`**
   - Enabled full `Serialize` coverage across all public content model fields (`SiteContent`, `Identity`, `SkillsDoc`, `Record`, `Project`, `WikiArticle`, `BlogPost`, including previously skipped `body_md`, `body_html`, `headings`, `internal_links`, and frontmatter metadata such as `blog.{author,date,tags,slug}` and `wiki.{category,updated,tags,slug}`).
   - Updated `check_privacy_and_nda` to traverse canonical `serde_json::to_value(content)` / `serde_json::to_string(content)` plus generated Atom XML, RSS XML, sitemap XML, and wiki client search JSON.
   - Added table-driven negative tests placing prohibited inputs in every public field across `identity`, `skills`, `records`, `projects`, `wiki`, and `blog`.

4. **[Low] Removal of split literal fragments & redacted privacy errors**
   - Removed all split literal fragments (`concat!(...)`) of operational identifiers and workstation metadata from `crates/site-content/src/validate.rs` and `crates/site-server/tests/release_and_privacy_gates.rs`.
   - Replaced exact private token/phrase checks with irreversible domain-separated `blake3` digests (`blake3::hash(b"km-privacy-v1:" || norm)`) in `crates/site-content/src/privacy_digests.rs` paired with generic structural detectors (`/home/<user>`, private/CGNAT/link-local IPv4, IPv6 ULA ranges, and PEM/SSH/age key headers and tokens) in `crates/site-content/src/privacy.rs`.
   - Standardized privacy error output to `{loc}: matched prohibited privacy rule` without echoing matched strings.

## Versioning & Packaging Changes

- Added `version = "0.1.1-alpha.1"` under `[workspace.package]` in `Cargo.toml`, inherited via `version.workspace = true` across `site-content`, `site-app`, and `site-server`, and synced `Cargo.lock`.
- Updated `scripts/build-bundle.sh` default version to `0.1.1-alpha.1`.
- Updated `SECURITY.md` with supported versions and `v0.1.1-alpha.1+` security controls.
